App Analysis — Video Observations

What was identified from the recorded demo

📌 Task List Screen (Main)

Tasks grouped by temporal sections: Overdue (red label), Today (cyan), Tomorrow, Next Week, and No Date. Each card shows task title, due date/time (red when overdue), repeat icon, and list name tag.

📝 Task Detail / Edit Screen

Full task editor with: text field + voice input, "Task finished?" checkbox, due date picker, time picker, notification summary, repeat frequency dropdown (No repeat / Once a Week), and Task List dropdown with inline "New List" creation.

📂 Task Lists Manager

Separate screen showing all lists (Default, Shopping, Wishlist) with task count, overdue count in red, inline Edit List dialog (rename), and delete controls per list.

⚡ Quick Task Input

Persistent sticky bar at the bottom: "Enter Quick Task Here" text field + microphone icon for voice-to-text task creation. Floating + FAB for full task creation. Toast messages: "Task Added", "Task Deleted".

🔍 Header Controls

Top bar: App logo (circle checkmark), current list dropdown (All Lists / specific list), search icon, and 3-dot overflow menu.

🔁 Repeat System

Recurring tasks supported. Repeat icon shown on task cards. Options visible: No repeat, Once a Week (implying daily, monthly etc. options exist).

⚡ Performance

API response <200ms. React renders optimized with useMemo / useCallback. MongoDB indexed on userId, dueDate, listId.

🔐 Security

JWT tokens (15min access + 7-day refresh). Bcrypt password hashing (salt rounds: 12). Helmet.js + CORS. Rate limiting on auth routes.

📱 Responsive

Mobile-first. Designed for 360–430px width. Progressive Web App (PWA) support for add-to-homescreen + offline cache.

🌍 Scalability

Stateless REST API. MongoDB Atlas free tier → M10 upgrade path. Redis for session/cache (future). Horizontally scalable Express.

Core Features

Full feature breakdown for MVP and V2

📝

Smart Task Management

Full CRUD with rich fields: title, due date/time, repeat, list assignment, completion status. Quick-add from persistent bottom bar.

📅

Temporal Grouping

Auto-groups tasks into Overdue, Today, Tomorrow, Next Week, No Date using server-computed and client-rendered date logic.

🔁

Recurring Tasks

Tasks repeat on schedule (Daily / Weekly / Monthly / Custom). When completed, the next occurrence auto-generates.

🔔

Smart Notifications

Daily 8 AM summary of tasks due today. Individual alerts at task time. Web Push API (PWA) or email fallback.

📂

Custom Lists

Users create/rename/delete lists (Work, Personal, Shopping etc.). Default list always exists. All Lists view aggregates everything.

🎙

Voice Input

Microphone button uses Web Speech API for hands-free task entry. Works in quick-bar and full task form.

🔍

Global Search

Real-time search across all task titles in all lists. Results highlight matched text.

📤

Share Task

Native Web Share API to share task title + due date via messaging apps, email, or copy link.

MERN Technology Stack

Full library and tooling decisions

⚛️ Frontend (React)

React 18 React Router v6 Redux Toolkit RTK Query Axios date-fns React Hook Form Framer Motion Material UI Vite

React 18 with concurrent features. Redux Toolkit for global state (tasks, lists, auth). RTK Query for server state + caching. date-fns for timezone-safe date manipulation. Material UI with custom theme matching app colors.

🟢 Backend (Node + Express)

Node.js 20 LTS Express 4 jsonwebtoken bcryptjs express-validator helmet cors express-rate-limit node-cron web-push

RESTful API with Express. node-cron runs daily notification scheduler at 7:50 AM. web-push sends Web Push notifications to PWA users. express-validator for all input sanitization.

🍃 Database (MongoDB)

MongoDB Atlas Mongoose 7 Mongoose Timestamps MongoDB Indexes

MongoDB Atlas M0 (free) to start. Mongoose schemas with validation. Compound indexes on (userId + dueDate) and (userId + listId) for fast queries. TTL indexes for expired token cleanup.

⚙️ DevOps & Tooling

Railway / Render (BE) Vercel (FE) GitHub Actions CI Jest + Supertest ESLint + Prettier dotenv Mongoose

Frontend on Vercel (free CDN + edge). Backend on Railway (auto-deploy from main branch). GitHub Actions runs lint + test on every PR. Jest + Supertest for API integration tests.

REST API Specification

All endpoints with methods and descriptions

Auth Routes — /api/auth

POST
/api/auth/register
Register new user. Returns access + refresh tokens.
POST
/api/auth/login
Login with email + password. Returns JWT tokens.

Refresh access token using refresh token in cookie.

/api/auth/me
Get current authenticated user profile. 🔐 Protected.

Task Routes — /api/tasks 🔐 All Protected

GET
/api/tasks?listId=&completed=&group=true
Get all tasks for user. Query params: filter by listId, completion, enable temporal grouping.
POST
/api/tasks
Create new task. Body: {title, dueDate, dueTime, repeat, listId}
GET
/api/tasks/:id
Get single task by ID.
PUT
/api/tasks/:id
Update task (title, date, repeat, list, completed).
PATCH
/api/tasks/:id/complete
Toggle task completion. Auto-generates next recurrence if repeat≠none.
DEL
/api/tasks/:id
Delete task. Soft-delete pattern for undo support.
GET
/api/tasks/search?q=
Full-text search across all task titles for the user.

GET
/api/lists
Get all task lists for the user (includes task count + overdue count).

/api/lists
Create new list. Body: {name}
PUT
/api/lists/:id

DEL

Delete list and move its tasks to Default list.

Authentication Architecture

JWT access + refresh token strategy

// JWT Strategy — authMiddleware.js const protect = async (req, res, next) => { const token = req.headers.authorization?.split(' ')[1]; if (!token) return res.status(401).json({ message: 'No token' }); const decoded = jwt.verify(token, process.env.ACCESS_SECRET); req.user = await User.findById(decoded.id).select('-password'); next(); }; // Tokens: ACCESS = 15min | REFRESH = 7d (httpOnly cookie) // Rotation: new refresh token issued on every /refresh call

Access Token

Expiry: 15 minutes. Stored in memory (Redux state). Sent in Authorization header.

Refresh Token

Expiry: 7 days. Stored in httpOnly cookie. Hashed in DB. Rotated on each use.

Password

Bcrypt with salt rounds: 12. Never returned in API responses (select: false).

GitHub Actions:
1. On push → run ESLint + Jest
2. On merge to main → deploy BE to Railway
3. Vercel auto-deploys FE on every push

Railway built-in logs for BE. Vercel Analytics for FE performance. MongoDB Atlas performance advisor for slow queries. Sentry (future) for error tracking.
